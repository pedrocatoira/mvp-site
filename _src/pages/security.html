How the app runs

MVP for Jira is built on Atlassian Forge. Its code and data are hosted by Atlassian, inside Atlassian’s cloud. Catoira Consulting Inc runs no servers for the app, and the app makes no calls to anything outside Atlassian: no external services, analytics or trackers.

What the app stores

The app stores only what it needs to draw your maps, in Atlassian’s Forge hosted storage for your site:

DataWhat it contains
MVPsThe MVP’s title, its steps and lanes (titles, order, linked release ids), the Jira project id, and the Atlassian account id of the person who created it
Card positionsFor each issue on an MVP: the Jira issue id, its lane and step, its order, and when it was added
LookupsWhich issue ids and release ids belong to which MVP, so changes in Jira reach the right maps
Site settingsThe settings a Jira admin chooses on the settings page

The app does not store issue summaries, descriptions, comments, attachments or any other issue field, nor people’s names, email addresses or avatars, nor any password or token. Issue details are read from Jira when a map is shown, as the person viewing it.

Your browser remembers which MVP you last opened in each project, so the tab opens where you left it.

Who can see and change what

  • Every request to Jira is made as the signed-in person, so Jira’s own permissions decide what each person can see and change. People never see issues that Jira hides from them, and the app reveals nothing about such issues.
  • The app changes only two Jira fields, and only when a person acts: story points (when edited on a card) and fix versions (when cards move between lanes linked to releases, if a Jira admin leaves that setting on). Fix versions are added and removed individually, so other versions on an issue are never overwritten.
  • Permission and plan checks happen on the server side for every action, not in the browser.
  • Catoira Consulting Inc has no access to your Jira site or to the app’s stored data.

Permissions the app requests

PermissionWhy
read:jira-workRead issues, statuses, fields, releases and permissions to draw the map
write:jira-workUpdate story points and fix versions when a person does so on the map
storage:appKeep MVPs, card positions and settings in Forge hosted storage

Data residency

App data is kept in Atlassian’s Forge hosted storage, which supports Atlassian data residency. If your organization pins its Jira data to a location, the app’s data is kept in the same location and moves with it.

Logs

When something goes wrong, the app writes a short error log line to Atlassian’s Forge logs. Log lines contain ids (MVP, issue or account id) and Jira’s error code, never issue content. Atlassian keeps these logs for a limited period. Your site admin can turn off log sharing with app developers in Atlassian Administration at any time.

Retention and deletion

  • Data is kept until someone deletes it. Deleting an MVP removes its map; removing an issue from an MVP removes its card; deleting an issue in Jira removes it from every MVP automatically.
  • A Jira admin can remove everything at once with Delete all app data on the settings page. This never touches Jira issues.
  • If a subscription ends, nothing is deleted; the app switches to a limited mode.
  • Uninstalling: Atlassian soft-deletes the app’s stored data and then removes it under Atlassian’s data retention policy. A reinstall starts with empty data; for a limited period after uninstalling (currently 21 days) a site admin can ask Atlassian to reconnect the previous data. For immediate, verifiable removal, use Delete all app data before uninstalling.

Our practices

  • Code changes are reviewed and run through automated tests, including checks that every action verifies permissions and validates its input.
  • Dependencies are installed from a lockfile and audited before each release.
  • The app follows the principle of least privilege: it requests only the permissions listed above.
  • We follow Atlassian’s Security Bug Fix Policy for Marketplace apps.

Report a security issue

Email support@catoira.app with “Security report” in the subject. Include the steps to reproduce, the impact you see, and how to reach you. We acknowledge reports within three business days and keep you updated until the issue is fixed. Please give us a reasonable time to fix an issue before disclosing it publicly, and don’t access or change data that isn’t yours while testing.
